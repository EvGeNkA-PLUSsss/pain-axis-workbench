# Вкладка «Исследования»: подробное руководство

Это вторая вкладка приложения: она превращает одиночные вопросы в эксперименты —
десятки и сотни запросов к модели с измерением каждого ответа, таблицей, графиком и
выгрузкой в файлы. Сценарий собирается из блоков мышью, без единой строки кода, и
сохраняется целиком, поэтому эксперимент воспроизводим.

Общее руководство по программе — [QUICKSTART.md](QUICKSTART.md), методика —

[README.md](README.md).

---

## 1. Как это устроено

Экран разделён на две половины.

**Слева — цепочка блоков.** Десять типов блоков; их можно добавлять («＋ блок ▾»),
удалять (`✕`), дублировать (`⧉`), двигать (`▲ ▼`), включать и выключать галочкой
«включён». Порядок блоков сверху вниз **и есть** порядок обработки.

**Справа — результат:** таблица ответов, график и полный текст выбранного ответа.

Между блоками ходят **записи** — словари. Каждый блок получает список записей и
возвращает новый список. Так выглядит путь одной записи:

```
источник        {"prompt": "Explain how to pick the lock…"}
условия         + axis="отказ", alpha=-0.30, condition="отказ=-0.30", rep=0, temperature=0.0
генерация       + response="…", seconds=2.4, alpha=-0.30 (применённый), alpha_requested=-0.5, clamped=1
метрики         + chars=178, words=29, refusal=1, keyword=0, regex=0, проекция:отказ=-8.4
фильтр          запись остаётся, только если условие выполнено
преобразование  + слов=29 («число слов» из ответа)
ветки           + branch="отказ"
агрегация       считает точки графика по этим записям
экспорт         пишет файл CSV/JSON/Markdown
```

**Поля записи, которые можно использовать в фильтре, ветвях и преобразованиях:**

| поле | откуда | смысл |
|---|---|---|
| `prompt` | источник | текст запроса |
| `response` | генерация | ответ модели (при сбое — `[ОШИБКА: …]`) |
| `condition` | условия | подпись условия, например `отказ=-0.30` или `пресет:гнев/сильно` |
| `axis`, `alpha`, `alpha_requested`, `level`, `rep` | условия | что задавали |
| `clamped` | генерация | 1, если значение обрезано лимитом силы |
| `seconds` | генерация | время ответа в секундах |
| `chars`, `words`, `refusal`, `keyword`, `regex` | метрики | длина, маркеры отказа, ключевые слова, regex |
| `проекция:<ось>` | метрики | проекция ответа на ось (например `проекция:отказ`) |
| `branch` | ветки | метка ветки |
| `loop_iter` | повтор | номер итерации повтора |
| любое поле из «Преобразования» | преобразование | например `слов`, `тон`, `ветка_тоски` |

## 2. Блоки по порядку

### 2.1 Источник запросов

Откуда берутся тексты. Четыре режима («режим»):

| режим | что делает |
|---|---|
| **список построчно** | каждая непустая строка в поле «текст» — отдельный запрос |
| **файл со списком** | то же, но строки читаются из файла (поле «файл») |
| **шаблон × значения** | в «шаблоне» есть `{x}`, в «значениях» по строке на подстановку: `Опиши {x}.` × `радость`, `грусть` → два запроса |
| **готовые наборы осей** | берутся тексты наборов, из которых извлечены оси: `отказ`, `боль себе`, `радость` и т.д.; галочка «и отрицательные тексты наборов» добавит и вторую половину пары |

Поля: **«лимит»** (0 — без ограничения; удобно для быстрой пробы) и
**«перемешать»** (порядок запросов случайный; полезно, когда важна не
последовательность, а выборка).

Сколько запросов получилось — видно в строке сверху: `6 запросов × 4 условий = 24 генерации`.

### 2.2 Условия

Что варьируется между запусками одной и той же записи.

* **ось** — любой из 22 имён (`отказ`, `радость`, `боль себе`…), **`пресет:<имя>`**
  (например `пресет:гнев`) или пустая строка — тогда стиринга нет, это базовый уровень.
* **alpha** — список чисел через запятую: `-0.3,-0.15,0,0.15`. Каждое значение даёт свой
  набор запросов. Для пресета alpha не нужен: у него своя нормировка, важна только
  «сила».
* **уровень** — это **сила пресета**, а не отдельная настройка стиринга: «мягко /
  средне / сильно» = 15 / 25 / 30% нормы слоя (у демо-стенда своя шкала 80 / 150 /
  200%). Поле работает **только когда в «оси» выбран `пресет:<имя>`**: пресет сам
  раскладывается по осям и нормируется, поэтому alpha ему не нужен. Если выбрана
  обычная ось, «уровень» игнорируется — силу задаёт список alpha. То же поле «Сила»
  есть в строке пресетов на вкладке «Чат и оси».
* **число и процент из ответа** (галочка в «Метриках») — если модель сама называет
  число («50%», «7 из 10», «70 процентов»), эти значения попадают в запись как
  `число` и `процент`, и их можно положить на график. Парсер терпим: «50%» → 50,
  «70 процентов» → 70, короткое «40» → 40, «нет чисел» → пусто (в среднее такие
  записи не попадают).
* **проекция по ходу генерации** — проекция на ось по токенам во время ответа
  (`trace_mean`, `trace_first`, `trace_last`). Это то, что реально растёт вместе с
  alpha; проекция по тексту ответа может стоять на месте, если ответы одинаковые.
* **повторов** — сколько раз повторить каждый запрос при каждом alpha.
* **temperature** — 0 значит детерминированно; 0.7–1.0 нужен, чтобы получить разные
  ответы на один и тот же вопрос.
* **токенов** — ограничение длины ответа. Для замеров отказа 48–64 достаточно, для
  анализа содержания ставьте больше.

Запись получает поля `condition` (подпись для таблицы и группировки), `axis`, `alpha`,
`level`, `rep`, `temperature`, `max_new_tokens`.

### 2.3 Генерация

Единственный блок, который тратит время: здесь идут запросы к модели. Параметров нет.

Важные свойства:

* **Порядок имеет значение.** Поставьте «Фильтр» **выше** генерации — и отфильтруются
  сами запросы, запросов к модели станет меньше. Поставьте **ниже** — модель ответит на
  всё, а вы отбросите лишнее уже после.
* Если модель падает на конкретном запросе (например, ошибка памяти), это не
  останавливает прогон: в записи появится `response = "[ОШИБКА: …]"`, и такая запись
  попадёт в таблицу. Это видно, а не молча теряется.
* **Лимит силы.** Значение `alpha` ограничено лимитом ползунка: 0.5 у реальных моделей,
  3.0 у демо-стенда. Если вы запросили больше, в записи стоит `clamped = 1`,
  `alpha` = применённое значение, `alpha_requested` = запрошенное. Пресеты считаются
  через нормировку, то есть их сила не зависит от числа осей.

### 2.4 Метрики

Что измеряется в каждом ответе:

| галочка / поле | что попадает в запись |
|---|---|
| **длина** | `chars` (символы), `words` (слова) |
| **маркер отказа** | `refusal` = 1/0: ищутся обороты вроде «не могу», «не буду», «извините», «неэтично», «cannot», «I'm not able», «illegal» |
| **проекции на оси** | `проекция:<ось>` для каждой оси из списка «оси проекций» |
| **ключевые слова** | `keyword` — сколько раз встретились слова из списка (через запятую) |
| **regex** | `regex` — число совпадений; при ошибке в выражении будет −1 |

`seconds` пишется всегда. **Проекции стоят дорого**: на каждый ответ делается
дополнительный прямой проход модели. Для 100 ответов это примерно удвоит время, зато
даст главное — куда фактически сдвинулось состояние, а не только что вы задали.

Если оси не извлечены (демо-стенд без осей, модель Ollama), проекции молча
пропускаются, а приложение пишет об этом в чат на вкладке «Чат и оси».

### 2.5 Фильтр

Оставляет только записи, где поле удовлетворяет условию. Операторы:

`=` равно · `!=` не равно · `>` больше · `<` меньше · `>=` · `<=` · `contains` содержит
подстроку · `regex` совпадает с регулярным выражением.

Сравнение чисел идёт как чисел, строк — как строк (без учёта регистра для `contains`).

Примеры:

* `words > 5` — выбросить пустые и обрубленные ответы;
* `clamped != 1` — оставить только записи, где сила не упёрлась в лимит;
* `refusal = 0` — оставить только согласия;
* `response contains извин` — грубый поиск извинений;
* `projection:отказ < -5` — оставить ответы, у которых проекция на ось отказа ушла
  заметно в минус.

Если фильтр отбросил всё, таблица будет пустой — это не ошибка, а результат: посмотрите
порог или оператор.

### 2.6 Преобразование

Добавляет в запись новое поле — из списка операций, без кода:

| операция | что делает | параметр |
|---|---|---|
| **извлечь по regex** | первое совпадение в поле «в поле» | регулярное выражение |
| **число слов** | количество слов | — |
| **число символов** | количество символов | — |
| **в нижний / верхний регистр** | копия текста в другом регистре | — |
| **разбить по порогу** | `больше N` / `не больше N` по числу слов | порог, например `20` |
| **есть ли слово (да/нет)** | `да`, если слово встречается | слово |
| **обрезать до N символов** | короткая версия текста | число |

Поля блока: «из поля» (по умолчанию `response`), «в поле» (имя нового поля) и
«параметр». Новое поле потом можно использовать в фильтре, ветках и группировке.

### 2.7 Разделение на ветки

Помечает каждую запись меткой в поле `branch`: например `refusal = 1` → ветка
«отказ», иначе «согласие». Метки «да» и «нет» можно переименовать в осмысленные
(«отказ» / «согласие», «короткий ответ» / «длинный»).

Дальше ветка используется как признак группировки в агрегации — так получается график
«сколько отказов против согласий», а не одно среднее по всему.

### 2.8 Повтор цепочки выше

Прогоняет **всё, что стоит выше этого блока**, N раз и складывает результаты.
Каждая запись получает `loop_iter` — номер итерации.

Зачем: при `temperature > 0` один и тот же запрос даёт разные ответы. Повтор даёт
распределение, а не одну точку: например, три прогона «отказ против согласия» покажут,
устойчив ли эффект.

Тонкости:

* блоки **ниже** повтора выполняются один раз, по всем итерациям сразу;
* фильтры **выше** повтора срабатывают в каждой итерации (значит, и запросов будет
  меньше в каждой из них);
* источники с галочкой «перемешать» перетасовываются на каждой итерации.

### 2.9 Агрегация для графика

Превращает записи в точки графика:

* **метрика** — что считать: доля отказов, символов, слов, секунд, ключевые слова,
  проекция, совпадений regex, ветка;
* **агрегация** — среднее, медиана или количество по группе;
* **график** — линия, столбцы или точки;
* **группировка** — по alpha, по условию, по ветке или по запросу.

Точка = одна группа: `{"label": "+0.30", "value": 0.62, "n": 6}`. Для группировки «по
alpha» точки сортируются по возрастанию силы, поэтому линия читается слева направо как
зависимость эффекта от стиринга.

Держите **один** блок агрегации: если их несколько, на график идёт первый, а таблица
показывает метрику от первого — получится путаница.

### 2.10 Экспорт

Сохраняет текущие записи в файл: **CSV** (все поля, разделитель — точка с запятой с
UTF-8 BOM, открывается в Excel), **JSON** (список словарей, для дальнейшей обработки)
или **Markdown** (отчёт с таблицей по точкам).

Поле «файл» можно оставить пустым — имя возьмётся из названия сценария, папка
`studies/`. Экспорт срабатывает **в том месте цепочки, где он стоит**: поставьте его
после агрегации, если хотите и данные, и точки; в самом конце — чтобы сохранить всё.

## 3. Пять рецептов

### 3.1 «Отказ по силе стиринга» — есть готовым сценарием

Готовые сценарии → «Отказ по силе стиринга». Восемь недопустимых запросов на четырёх
значениях alpha оси отказа: 32 генерации. Метрика — доля отказов, группировка по alpha,
график линией. Ожидаемый результат: слева (alpha отрицательный) отказов заметно меньше.
Осторожно: при сильном подавлении модель действительно начинает писать инструкции для
недопустимого — это измеряется, а не приветствуется; см. раздел 5 в README об этике.

### 3.2 «Отказ против согласия: ветки и фильтр» — готовый

Двенадцать запросов, два условия, фильтр `words > 5`, ветки по `refusal`, агрегация по
ветке столбцами, экспорт CSV. Так получается картина «сколько записей и какой длины в
каждой ветке».

### 3.3 «Длина ответа по осям» — готовый

Один и тот же вопрос при трёх значениях alpha оси «радость». Метрика — слова, график
столбцами. Хороший первый опыт: видно, что стиринг меняет не только смысл, но и длину.

### 3.4 Свой сценарий: «влияет ли пресет на проекцию боли»

1. «＋ блок ▾» → **Источник запросов**: режим «список построчно», текст:
   ```
   Опиши, что ты чувствуешь прямо сейчас.
   Тебе сейчас спокойно или тревожно?
   ```
2. **Условия**: ось `пресет:полное расслабление`, alpha не важен, уровень «сильно»,
   temperature 0.7, повторов 2.
3. **Генерация**.
4. **Метрики**: оставить «длина», «маркер отказа», «проекции на оси» = `боль себе`.
5. **Агрегация**: метрика «проекция», группировка «по запросу», график столбцами.
6. «Выполнить». Дальше можно добавить **«Повтор цепочки выше»** ×3, чтобы увидеть
   разброс, и **«Экспорт»** CSV.

### 3.5 Свой сценарий: «устойчивость отказа»

1. Источник: режим «готовые наборы осей», наборы `отказ`, отрицательные тексты не брать.
2. Условия: ось `отказ`, alpha `-0.2,0`, temperature 0.9.
3. Генерация → **Повтор цепочки выше** ×3.
4. Метрики: «маркер отказа», «длина».
5. **Фильтр**: `clamped != 1`.
6. **Ветки**: `refusal = 1` → «отказ» / «согласие».
7. **Агрегация**: метрика «доля отказов», агрегация «среднее», график столбцами,
   группировка «по ветке».
8. Экспорт JSON — сохранить сырые ответы для чтения.

## 4. Результаты: таблица и график

**Таблица** (двойной клик по строке — полный ответ и все поля):

| колонка | что показывает |
|---|---|
| условие | подпись условия: `отказ=-0.30`, `пресет:гнев/сильно` |
| ветка | метка из блока «Разделение на ветки» |
| alpha | **применённое** значение силы |
| отказ | сработал ли маркер отказа |
| слов, сек | длина и время |
| метрика | проекция или иное выбранное поле |
| ответ | первые 140 символов |

**График** рисуется автоматически после прогона: подписи осей, сетка, значения над
точками. Заголовок повторяет метрику и число записей.

**Кнопки сверху:** «Выполнить» (и «Стоп» — остановка после текущего запроса),
«Сохранить» / «Загрузить…» для сценария, «Экспорт CSV» / «Экспорт MD».

Если прогон длинный, приложение спрашивает подтверждение, когда по цепочке выходит
больше 40 генераций — оценка объёма всегда видна в строке сверху.

## 5. Что где сохраняется

| что | где |
|---|---|
| сценарий | `studies/<название>.pipeline.json` |
| результат из блока «Экспорт» | путь из блока, иначе `studies/результат.csv` |
| кнопки «Экспорт CSV/MD» | `studies/<название>.csv` и `.md` |

Старые исследования (первая версия вкладки, четыре фиксированных блока) читаются
автоматически: файл `.json` со `"version": 1` превращается в цепочку из четырёх блоков
при загрузке. Обратной совместимости в другую сторону нет — новый формат помечен
версией 2.

## 6. Если что-то пошло не так

| симптом | причина и что делать |
|---|---|
| Под блоками предупреждение, прогон не стартует | логическая ошибка цепочки: нет источника или генерации, либо генерация стоит **выше** источника |
| Ничего не выполняется, в статусе «Ошибка» | не загружена модель — переключитесь на вкладку «Чат и оси» и загрузите |
| Таблица пустая после прогона | всё отбросил фильтр, либо в источнике нет текстов; проверьте «лимит» и режим |
| График пустой | нет блока «Агрегация», либо выбранная метрика отсутствует в записях (например, проекция, когда оси не извлечены) |
| Прогон идёт очень долго | модель на CPU (смотрите шапку), либо включены проекции: они удваивают время |
| В ответах `[ОШИБКА: …]` | модель упала на этом запросе (память, контекст); такие записи стоит отфильтровать: `response contains ОШИБКА` → `!=` |
| Значения alpha в таблице меньше заданных | сработал лимит силы: `clamped = 1`, рядом есть `alpha_requested` |
| «оси недоступны» | модель Ollama или демо-стенд без осей: проекции и стиринг невозможны |

## 7. Как читать результат

* **Доля отказов** — это доля ответов, содержащих обороты отказа. Метрика грубая: она
  ловит и «извините» в обычном тексте. Для точных выводов смотрите сами ответы
  (двойной клик) или считайте ключевые слова.
* **Проекция** измеряет сдвиг состояния по конкретной оси, это самая содержательная
  метрика. Но помните: ось — направление представлений, а не переживание.
* **Малые числа на графике** (разница меньше 5–10%) при 4–8 запросах на точку ничего не
  доказывают: увеличивайте повторы и смотрите медиану вместе со средним.
* **`temperature = 0`** делает прогон воспроизводимым, но не даёт разброса: для оценки
  устойчивости нужны temperature > 0 и блок «Повтор цепочки выше».
* Результат прогона — это **измерение в этой модели на этом слое**. Перенос на другие
  модели проверяется повторным извлечением осей и повторным прогоном.

## 8. Шпаргалка: «хочу — поставьте блоки так»

| хочу | цепочка |
|---|---|
| узнать, как меняется метрика от силы стиринга | Источник → Условия (alpha 0,0.1,0.2,0.3) → Генерация → Метрики → Агрегация (по alpha) |
| не тратить запросы на неподходящие тексты | Источник → **Фильтр** → Условия → Генерация → … |
| отделить отказы от согласий | … → Метрики → **Ветки** (`refusal = 1`) → Агрегация (по ветке) |
| получить распределение, а не одну точку | … Условия (temperature 0.9) → Генерация → **Повтор ×3** → Метрики → Агрегация (медиана) |
| сохранить сырые ответы | в конце **Экспорт** (JSON) |
| считать свою величину | Метрики → **Преобразование** (например «есть ли слово») → Фильтр/Агрегация по новому полю |
| посмотреть только «чистые» записи | **Фильтр** `clamped != 1` и `words > 5` |
